## Phase 1: Action/event schema hardening + GrowthGuard → ProofLayer rename

**Why first:** the spec (Section 6.5) flags `GrowthGuard` as a brand-risk name collision with an existing company. Every later phase (Truth Graph, SafeDeploy, Shopify connector) adds more code that would reference the old name if this isn't done first — rework avoided by doing it now. The schema hardening (real enums instead of loose strings for `Action.status` and `GuardResult.outcome`) is what Phase 2's risk tiers and policy versions get added to — doing it as part of the rename means one migration, not two.
